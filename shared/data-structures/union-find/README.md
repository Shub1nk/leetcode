# UnionFind

Система непересекающихся множеств (**DSU** — disjoint set union) на дженерике. Держит «лес деревьев»: каждый элемент показывает на родителя, корень дерева — представитель всего множества. Отвечает на вопрос «в одной ли группе два элемента» за почти константу.

Дженерик, а не числовой: ключ — любой `T` со сравнением по значению. Внутри две `Map` вместо массивов, поэтому узлы могут быть строками, координатами и т.п., без привязки к индексам `0..n-1`.

## API

```ts
const uf = new UnionFind<string>(["a", "b", "c"]); // можно и пустой: new UnionFind()

uf.add(x);          // зарегистрировать новый элемент (идемпотентно)
uf.find(x);         // корень (представитель) множества x → T
uf.union(a, b);     // слить множества → boolean: true если реально слил
uf.connected(a, b); // в одной ли группе → boolean
uf.size(x);         // размер множества, которому принадлежит x → number
uf.count;           // сколько сейчас непересекающихся множеств
```

`union` возвращает `boolean` неспроста: `false` означает «уже были в одном множестве» — это готовый детектор цикла (задачи вроде Redundant Connection).

`find` / `union` / `size` на незарегистрированном ключе **бросают** `UnknownElementError` (сообщение экспортируется как `UNION_FIND_ERROR_ELEMENT_NOT_FOUND`). Осознанно строго: ловит опечатки и рассинхрон, вместо тихого создания «призрачного» узла.

## Контракт ключа

`T` обязан иметь **равенство по значению**: либо примитив (`string` / `number`), либо стабильная ссылка на объект.

Причина — `Map` сравнивает ключи через `SameValueZero`, для объектов это ссылочное равенство. Два разных объекта с одинаковыми полями — **разные ключи**:

```ts
new Map().set({ r: 0, c: 1 }, "x").get({ r: 0, c: 1 }); // undefined!
```

Поэтому доменный объект приводи к ключу **на стороне вызова**: координату `(r, c)` — в строку `` `${r},${c}` `` или число `r * cols + c`; вершину графа — в её `id` / индекс. DSU оперирует идентичностью, данные узла живут в твоей структуре отдельно.

## Реализация

Три поля: `parent: Map<T, T>` (элемент → родитель; корень показывает сам на себя), `sizes: Map<T, number>` (размер множества, валиден **только на корнях**) и счётчик `count`.

Обе классические оптимизации:

- **Path compression** в `find` — второй проход перевешивает узлы пути напрямую на корень, дерево остаётся плоским. Цикл итеративный, а не рекурсивный: длинная цепочка не переполнит стек.
- **Union by size** — меньшее дерево вешаем под корень большего (`parent.set(small, big)`), суммарный размер кладём на победителя. Держит деревья мелкими.

`size` читает размер через `find(x)` — размер живёт на корне, а не на самом элементе. `connected` — сравнение корней. Конструктор просто гоняет `add` по `Iterable`, поэтому дубликаты во входе безопасны (регистрация идемпотентна).

## Сложность

- `find` / `union` / `connected` / `size`: **O(α(n))** амортизированно (α — обратная функция Аккермана, практически константа) — за счёт связки compression + by-size.
- `add`: O(1).
- Память: O(n).

## Заметки

- `union(x, x)` и повторный `union` уже связанных → `false`, счётчик не трогается.
