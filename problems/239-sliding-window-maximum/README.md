# 239. Sliding Window Maximum

**Сложность:** Hard

**Ссылка:** https://leetcode.com/problems/sliding-window-maximum/

## Условие

Дан массив `nums` и число `k` — размер окна. Окно едет слева направо по одной позиции за шаг. Вернуть массив максимумов каждого положения окна.

Ответов ровно `nums.length - k + 1`.

## Примеры

```
nums = [1,3,-1,-3,5,3,6,7], k = 3   → [3,3,5,5,6,7]
nums = [1], k = 1                   → [1]
```

## Ограничения

- `1 <= nums.length <= 10^5`
- `-10^4 <= nums[i] <= 10^4`
- `1 <= k <= nums.length`

## Решения

Оба подхода ведут **правый край** окна, левый вычисляется как `right - (k - 1)`. Общий вход — barrel `index.ts`, общие кейсы — `__tests__/cases.ts`.

### Решение 1 — брутфорс (`brute-force.ts`)

С него начали. Для каждого положения окна честный проход по его `k` элементам с накоплением максимума.

- **Сложность:** время `O(n·k)`, память `O(1)` сверх ответа.
- **TLE на LeetCode.** При `k ≈ n/2` это ~`2.5·10^9` операций; выигрыш нужен алгоритмический, никакая чистка констант не спасает.

Оставлен в репозитории намеренно: он заведомо правильный и годится в оракулы для сверки с деком на случайных входах.

### Решение 2 — монотонный дек (`monotonic-deque.ts`)

В деке лежат **индексы**, а не значения: проверка выхода за левую границу окна — вопрос о позиции. Значения по этим индексам всегда убывают, поэтому максимум текущего окна — всегда в голове.

Четыре шага на итерацию:

1. пока значение в хвосте `<=` пришедшего — `popBack`: такой элемент уже никогда не станет максимумом, потому что правее него стоит не меньший, который покинет окно позже;
2. `pushBack` текущего индекса;
3. если голова левее `windowLeftIndex` — `popFront`, она вышла из окна;
4. при `windowLeftIndex >= 0` дописать `nums[peekFront()]` в ответ — **`peek`, а не `pop`**: голова может быть максимумом и для следующих окон.

- **Сложность:** время `O(n)`, память `O(k)`.
- Вложенный `while` не ломает линейность: каждый индекс входит в дек один раз и выходит не более одного раза — амортизированная константа на шаг.

Путь от первого решения ко второму: брутфорс → кэшировать максимум и его индекс (ломается на убывающем массиве, где бесполезных элементов ноль) → хранить всю убывающую цепочку кандидатов, то есть монотонный дек.

## Заметки

- `Math.max(...window)` вместо накопления в переменной кладёт стек при больших `k` — спред разворачивается в аргументы.
- Дек берётся из `shared/data-structures/deque` (кольцевой буфер). Для отправки на LeetCode его можно заменить массивом с указателем `head`: `popFront` через `head += 1`, потому что `shift()` стоит `O(m)` и возвращает сложность к `O(n·k)`.
- Тонкое место — `<` против `<=` в проверке головы: индекс, равный левой границе, ещё **внутри** окна.
- Промежуточный вариант «кэшировать максимум и его индекс, пересчитывать только когда он выходит из окна» в репозиторий не попал: на случайных данных он быстр, но на убывающем массиве вырождается в те же `O(n·k)` — там максимум всегда на левом краю.
