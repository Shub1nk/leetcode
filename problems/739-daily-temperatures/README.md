# 739. Daily Temperatures

**Сложность:** Medium

**Ссылка:** https://leetcode.com/problems/daily-temperatures/

## Условие

Дан массив дневных температур. Для каждого дня вернуть, **сколько дней придётся ждать** до первого дня со строго более высокой температурой. Если такого дня не будет — `0`.

## Примеры

```
[73,74,75,71,69,72,76,73] → [1,1,4,2,1,1,0,0]
[30,40,50,60]             → [1,1,1,0]
[30,60,90]                → [1,1,0]
```

## Ограничения

- `1 <= temperatures.length <= 10^5`
- `30 <= temperatures[i] <= 100`

## Решение — монотонный стек (`monotonic-stack.ts`)

Ключевая перестановка мысли: **ответ для дня приходит не тогда, когда ты на нём стоишь, а когда встречается тот день, который его греет.** Стоя на дне `i`, ты ещё не знаешь его ответа — тёплый день где-то впереди. Значит день нужно оставить ждать и разрешить задним числом.

В стеке лежат **индексы дней, ответ для которых пока не найден**. Пришёл новый день — он разрешает всех, кто холоднее его, и сам встаёт ждать:

1. пока стек не пуст и сегодняшняя температура строго выше температуры на вершине — снимаем вершину и записываем ей `index - coolerDayIndex`;
2. кладём текущий индекс в стек.

Разрешить за один шаг можно **сразу нескольких** — отсюда `while`, а не `if`. На примере выше день с температурой `72` закрывает сразу два предыдущих.

Монотонность стека (температуры убывают от дна к вершине) — не правило, которое навязывается, а **следствие**: всё, что ниже пришедшего, немедленно снимается, значит остаться может только то, что выше.

`result` заполняется нулями заранее. Тогда дни, до которых тепло так и не дошло, остаются в стеке до конца и получают свой `0` бесплатно — разбирать остаток стека после цикла не нужно.

- **Сложность:** время `O(n)`, память `O(n)`.
- Вложенный `while` не ломает линейность: каждый индекс попадает в стек ровно один раз и покидает его не более одного раза, отсюда амортизированная константа на шаг.

## Заметки

- **Сравнение обязано быть строгим.** Условие просит день *строго* теплее, поэтому на равной температуре ответа ещё нет и снимать вершину нельзя. С `>=` решение молча выдаёт `[1,1,0]` там, где верно `[0,0,0]` — в тестах для этого лежит кейс из одинаковых температур.
- Индексы, а не температуры, в стеке нужны потому, что ответ — это расстояние между днями, и без позиции его не посчитать.
- Проверка на пустоту фактически выполняется дважды за итерацию: явно в условии `while` и повторно внутри `peek()`, который не доверяет вызывающему. Это осознанная цена безопасного API, читаемость важнее.
- **Для отправки на LeetCode** стек не нужен как класс — обычный массив уже стек (`push`, `pop`, `at(-1)`). Готовый вариант — в [`docs/leetcode-snippets.md`](../../docs/leetcode-snippets.md). Там же обычный `for` вместо `entries()`: последний аллоцирует пару `[index, value]` на каждый элемент, что в репозитории окупается читаемостью, а в горячем цикле — нет.
