# 111. Minimum Depth of Binary Tree

**Сложность:** Easy

**Ссылка:** https://leetcode.com/problems/minimum-depth-of-binary-tree/

## Условие

Дано бинарное дерево. Вернуть его **минимальную** глубину — число узлов на кратчайшем пути от корня до ближайшего **листа**.

Лист — узел, у которого нет ни левого, ни правого потомка. У пустого дерева глубина `0`.

## Примеры

```
[3,9,20,null,null,15,7]      → 2      (9 — лист на втором уровне)
[2,null,3,null,4,null,5,null,6] → 5   (вырождение вправо, лист один)
```

## Ограничения

- Число узлов в дереве — от `0` до `10^5`
- `-1000 <= Node.val <= 1000`

## Решения

Ключевое слово условия — **минимальная**, а не максимальная. Отсюда всё остальное: нужен ближайший лист, то есть кратчайший путь, и обход по уровням ложится на задачу естественнее обхода вглубь.

Оба подхода определяют лист одинаково — общий хелпер `isLeafNode` в `common.ts`.

### Решение 1 — обход в ширину (`bfs.ts`)

Очередь из `shared/data-structures/queue`, обход по уровням со счётчиком `levelSize`. Как только из очереди достаётся лист — возвращаем текущую глубину и выходим.

Корректность держится на том, что BFS посещает узлы в порядке **неубывающей глубины**: всё, что мельче, уже проверено и листом не оказалось, а глубже ещё не смотрели. Значит первый встреченный лист лежит на минимальной глубине.

- **Сложность:** время `O(n)` в худшем случае, память `O(w)` — максимальная ширина дерева.
- Ранний выход работает почти всегда: дообходить уровень не нужно.

Пустое дерево обрабатывается без отдельной ветки: корень кладётся в очередь только если он существует, а `return 0` после цикла достижим лишь тогда, когда очередь была пуста изначально.

### Решение 2 — обход в глубину с отсечением (`dfs.ts`)

Рекурсия сверху вниз: глубина едет вниз параметром, найденный минимум копится в замыкании. Ответ фиксируется **только на настоящем листе**.

Отсечение: если текущая глубина уже не меньше найденного минимума, спускаться дальше бессмысленно — любой лист внизу окажется только глубже. Классические ветви и границы.

- **Сложность:** время `O(n)` в худшем случае, память `O(h)` — высота дерева, глубина стека вызовов.

### Что быстрее

Замеры на LeetCode, один и тот же набор из 53 тестов:

| Подход | Время | Процентиль |
|---|---|---|
| BFS | **1 ms** | 92.47% |
| DFS с отсечением | 5 ms | 66.57% |
| DFS без отсечения | 8 ms | 23.19% |

Отсечение отыграло около трёх миллисекунд из семи. Оставшийся разрыв с BFS — накладные расходы рекурсии плюс то, что DFS всегда идёт сначала влево: отсечение включается только после того, как найден первый лист, то есть после полного спуска по левой ветке. BFS такой слепоты лишён.

По памяти подходы противоположны и выигрывают на разных формах дерева: широкое и мелкое — выгоден DFS (`O(h)` против `O(w)`), глубокое и узкое — BFS.

## Заметки

- **Ловушка одного ребёнка.** Форма рекурсии «снизу вверх» — `1 + min(глубина(left), глубина(right))` — на узле с единственным потомком даёт неверный ответ: пустое поддерево возвращает `0`, и минимум цепляется за него. На дереве `[1,2,null,3]` такая версия вернёт `1` вместо `3`. Здесь взята форма «сверху вниз», где ответ фиксируется только на листе, — в ней ловушки нет по построению.
- **Глубина рекурсии.** При `10^5` узлов вырожденное дерево даёт стек той же глубины, и рекурсивный обход рискует упасть. BFS к форме дерева нечувствителен.
- **Для отправки на LeetCode** очередь заменяется двумя массивами «текущий уровень / следующий» — тогда счётчик `levelSize` не нужен вовсе, граница уровня получается бесплатно. Готовый вариант — в [`docs/leetcode-snippets.md`](../../docs/leetcode-snippets.md).
