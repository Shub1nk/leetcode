# 70. Climbing Stairs

**Сложность:** Easy

**Ссылка:** https://leetcode.com/problems/climbing-stairs/

## Условие

Лестница из `n` ступенек. За один шаг можно подняться на 1 или на 2 ступеньки. Сколькими различными способами можно добраться до верха?

Способ — это набор шагов, сумма которых равна ровно `n`. Порядок шагов различает способы: `1+2` и `2+1` — разные ответы.

## Примеры

```
n = 2  → 2   (1+1, 2)
n = 3  → 3   (1+1+1, 1+2, 2+1)
n = 45 → 1836311903
```

## Ограничения

- `1 <= n <= 45`

## Вывод формулы

Разложение по **последнему шагу**. На ступеньку `n` можно попасть только двумя способами: прыжком с `n-1` или прыжком с `n-2`, третьего не дано. Значит все способы делятся на две кучки:

- закончившиеся шагом на 1 — до него стоял на `n-1`;
- закончившиеся шагом на 2 — до него стоял на `n-2`.

Кучки не пересекаются (у пути ровно один последний шаг) и покрывают всё (других длин шага нет), поэтому количества складываются:

```
f(n) = f(n-1) + f(n-2)
```

Верхняя граница `n = 45` даёт `1836311903` — умещается в `Number.MAX_SAFE_INTEGER`, `BigInt` не нужен. Точность поплыла бы после `n ≈ 78`.

## Решения

Оба подхода — одна и та же рекуррента, разница в направлении счёта. Общий вход — barrel `index.ts`, общие кейсы — `__tests__/cases.ts`.

### Решение 1 — таблица снизу вверх (`tabulation.ts`)

С него начали. Идём от базы к ответу. Формула смотрит только на два шага назад, поэтому всю таблицу держать незачем — хватает двух переменных, которые сдвигаются на каждой итерации.

- **Сложность:** время `O(n)`, память `O(1)`.

Базы (`0`, `1`, `2`) выписаны явными ранними возвратами. Случай `n = 2` избыточен — общий путь вернул бы то же самое, — но оставлен намеренно: все базовые значения видны в одном месте, а база в DP как раз то, на чём спотыкаются.

### Решение 2 — мемоизация сверху вниз (`memo.ts`)

Рекурсия буквально по формуле плюс кэш посчитанных значений. Направление обратное: от `n` вниз к базе.

- **Сложность:** время `O(n)`, память `O(n)` на кэш плюс глубина стека `O(n)`.

Кэш создаётся **внутри** `climbingStairs`, а не на уровне модуля: живёт один вызов и не протекает между тестами.

## Сложность

| подход | время | память |
|---|---|---|
| `tabulation` | `O(n)` | `O(1)` |
| `memo` | `O(n)` | `O(n)` |

## Заметки

- **Зачем кэш — измерено.** Наивная рекурсия без кэша на `n = 45` делает `2 269 806 339` вызовов против `45` с кэшем, разница в 50 миллионов раз (6.1 с против 0.3 мс). Дерево вызовов ветвится: без кэша возвращается только число, а вся промежуточная работа выбрасывается вместе со стековыми кадрами, и соседняя ветка строит то же поддерево заново. Глубина дерева растёт линейно, число узлов — экспоненциально. Кэш схлопывает дерево в граф: различных значений `f(k)` всего `n`.
- **Про `f(0)`.** Если брать базами `f(0)` и `f(1)`, то `f(0) = 1` — пустой набор шагов существует и он ровно один. Иначе `f(2) = f(1) + f(0) = 1 + 0` теряет путь `[2]`. Здесь выбраны базы `1` и `2`, где спорной ячейки нет вовсе.
- Комбинаторная формула у задачи существует: `f(n) = Σ C(n-k, k)` по числу двоек `k`. Выводится тяжелее рекуррентной и разваливается от любого усложнения условия (запрет ступеньки, цена шага) — DP нужен ровно там, где замкнутой формулы нет.
- Тест `n = 0` лежит вне ограничений (`1 <= n <= 45`), оставлен как фиксация выбранной базы.
