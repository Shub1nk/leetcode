# 198. House Robber

**Сложность:** Medium

**Ссылка:** https://leetcode.com/problems/house-robber/

## Условие

Вдоль улицы стоят дома, в каждом лежит какая-то сумма денег. Забрать можно из любых домов, кроме одного ограничения: **в двух соседних домах за одну ночь грабить нельзя** — их сигнализации связаны между собой и вызовут полицию.

Дан массив `nums`, где `nums[i]` — сумма в i-м доме. Вернуть максимальную сумму, которую можно унести, не потревожив сигнализацию.

## Примеры

```
nums = [1,2,3,1]     → 4    (дома 0 и 2: 1 + 3)
nums = [2,7,9,3,1]   → 12   (дома 0, 2 и 4: 2 + 9 + 1)
```

## Ограничения

- `1 <= nums.length <= 100`
- `0 <= nums[i] <= 400`

Массив из одного дома — допустимый вход. Нулевые суммы тоже разрешены.

## Решения

Оба подхода — **одна и та же формулировка состояния**, отличается только направление счёта. Этим задача отличается от [746](../746-min-cost-climbing-stairs/README.md), где подходы построены на разных постановках.

Общий разбор по пяти шагам:

| шаг | | 
|---|---|
| **состояние** | `f(i)` — максимум денег с домов `0…i` |
| **переход** | `f(i) = max(f(i-1), nums[i] + f(i-2))` |
| **база** | `f(0) = nums[0]`, `f(1) = max(nums[0], nums[1])` |
| **ответ** | `f(n-1)`, последняя ячейка |

Переход выводится разложением по последнему решению: дом `i` либо ограблен, либо нет. Не грабим — задача сводится к первым `i` домам, то есть `f(i-1)`. Грабим — забираем `nums[i]`, дом `i-1` под запретом, значит присоединиться может только `f(i-2)`. Кучки не пересекаются и покрывают всё, склеиваются через `max`, потому что состояние меряет максимум.

Ключевое в формулировке состояния — **отсутствие условия «дом `i` обязательно ограблен»**. Именно поэтому вариант «пройти мимо» учтён внутри, а ответ лежит в последней ячейке и не требует сборки из нескольких.

### Решение 1 — мемоизация сверху вниз (`memo.ts`)

С него начали. Рекурсия по формуле плюс кэш; порядок вычислений находится сам.

- **Сложность:** время `O(n)`, память `O(n)` на кэш плюс глубина стека `O(n)`.

### Решение 2 — таблица снизу вверх (`tabulation.ts`)

Тот же комплект, цикл вместо рекурсии. Стека не расходует.

- **Сложность:** время `O(n)`, память `O(n)`.

Память сжимается до `O(1)` парой переменных — переход смотрит только на два шага назад. Не сделано намеренно: таблица нагляднее, а `n <= 100` экономии не требует.

## Сложность

| подход | время | память |
|---|---|---|
| `memo` | `O(n)` | `O(n)` + стек `O(n)` |
| `tabulation` | `O(n)` | `O(n)` |

## Заметки

- **Жадность здесь ломается.** На `[2,1,1,2]` ответ `4` — дома `0` и `3`, то есть пропуск **двух подряд**. Ни «брать через один», ни «брать самое дорогое» такого набора не дают. Правило «нельзя соседних» разрешает пропускать сколько угодно, и иногда это выгодно.
- **Где ответ — отдельный шаг, но здесь он тривиален.** В отличие от 746, состояние не содержит ограничения на последний дом, поэтому `f` не убывает и `max(f(n-1), f(n-2))` был бы избыточен: любой допустимый набор из `0…n-2` допустим и в `0…n-1`.
- **Массив из одного дома** — легальный вход (`1 <= nums.length`). Без раннего выхода база `f(1) = max(nums[0], nums[1])` читает несуществующий `nums[1]` и кладёт в таблицу `NaN`. Работало бы «случайно» — испорченная ячейка не читается, — поэтому выход поставлен явно.
- **`NaN` в DP заразен.** `Math.max(NaN, x)` даёт `NaN`, а каждая ячейка зависит от предыдущих, поэтому одна порча за проход отравляет всю таблицу. Искать надо **первую** испорченную ячейку, а не ту, где заметил. Ловилось при попытке идти циклом через `nums.entries()`: он всегда стартует с нуля, а таблица должна заполняться с индекса `2` — первые две ячейки уже заданы базой.
- Размер таблицы — ровно `nums.length`: пишем индексы `0…n-1`. Полезная привычка — назвать вслух максимальный индекс, который будешь писать, и взять длину на единицу больше.
