# 1584. Min Cost to Connect All Points

**Сложность:** Medium

**Ссылка:** https://leetcode.com/problems/min-cost-to-connect-all-points/

## Условие

Дан массив `points`, где `points[i] = [xi, yi]` — точка на плоскости. Стоимость соединения двух точек — их **манхэттенское расстояние** `|xi − xj| + |yi − yj|`.

Нужно соединить все точки так, чтобы между любой парой был **ровно один** путь, с минимальной суммарной стоимостью. Вернуть эту стоимость.

## Примеры

```
points = [[0,0],[2,2],[3,10],[5,2],[7,0]]   → 20
points = [[3,12],[-2,5],[-4,1]]             → 18
```

## Ограничения

- `1 <= points.length <= 1000`
- `-10^6 <= xi, yi <= 10^6`
- Все точки различны.

## Решения

«Ровно один путь между любой парой при минимальной сумме» — это дословно **минимальное остовное дерево** (MST) на полном графе, где вес ребра = манхэттенское расстояние. Реализованы два канонических подхода: `kruskal.ts` и `prim.ts`, общий вход — barrel `index.ts`, общий хелпер расстояния — `common.ts`.

### Решение 1 — Крускал + Union Find (`kruskal.ts`)

Собираем все рёбра `[from, to, cost]` пар `i < j`, сортируем по весу, идём от дешёвого к дорогому и берём ребро, если `union(from, to)` слил две разные компоненты (иначе оно замкнуло бы цикл — пропускаем). Ранний выход по `count === 1`. Union Find — на индексах точек; вес в структуру не попадает, копится снаружи в `total`.

- **Сложность:** время `O(n² log n)` (сортировка `n²` рёбер), память `O(n²)` (список рёбер).
- **Плюсы:** прямолинейная логика «сортируй и объединяй»; обкатывает Union Find; естественно ложится на **разреженные** графы.
- **Минусы:** на плотном (полном) графе избыточен — хранит все `n²` рёбер и платит `log n` за сортировку.

### Решение 2 — Прим на массиве (`prim.ts`)

Дерево растёт из вершины `0`: держим `minDist[v]` (самое дешёвое ребро от `v` до дерева) и `inTree[v]`. На каждом из `n` шагов выбираем ближайшую не-в-дереве вершину (линейный поиск), прибавляем её к `total`, затем релаксацией удешевляем соседей.

- **Сложность:** время `O(n²)`, память `O(n)` — без списка рёбер и без сортировки.
- **Плюсы:** оптимален для **плотного** графа (как здесь); минимум памяти; Union Find не нужен — циклы невозможны по построению.
- **Минусы:** на разреженных графах массивная версия проигрывает — там выгоднее Крускал (или Прим на куче).

**Итог для 1584:** граф полный, так что по асимптотике Прим предпочтительнее (`O(n²)` vs `O(n² log n)`). Крускал оставлен как первый, «учебный», подход ради обкатки Union Find. При `n ≤ 1000` оба проходят мгновенно.

## Заметки

- Union-by-size + сжатие путей дают почти `O(α(n))` на операцию UF.
- Манхэттен целочисленный (без `√`/float), поэтому `total` остаётся целым.
- Оба решения считают только стоимость (`total`); сами рёбра дерева не восстанавливаем — задача просит цену, не структуру.
- Глубокое сравнение Прим/Крускал (свойство разреза, когда какой) — в obsidian-заметке.
